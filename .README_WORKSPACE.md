# INFILTRAITOR — the two workspaces

One repository, two working copies, two agents, one boundary between them.

**This file is identical on `main` and on `feat/design-interface-hud`, and that
is deliberate.** Until 2026-09-09 there were two different documents at this
same path — one per branch — which guaranteed an add/add conflict the first
time the branches met. Whoever opens either workspace should read the same
charter and see both roles, including the one that is not theirs.

| | Engine | Design |
|---|---|---|
| **Branch** | `main` (default, always stable) | `feat/design-interface-hud` |
| **Clone** | `…/PYTHON/INFILTRAITOR` | `…/PYTHON/INFILTRAITOR_DESIGN` |
| **Agent** | CLAUDE (Claude Code — Anthropic's CLI, currently Opus 5) | JAMES (Qwen 3.5 9B via LM Studio on PC LAN) |
| **Owns** | physics, voxel rendering, destruction, prediction, light, AI, coordinate math | UI, HUD, menus, input wiring, visual polish |
| **Charter** | [CLAUDE.md](CLAUDE.md) § "Process — what not to do" | [`../JAMES/.qwen/system-prompt.md`](../JAMES/.qwen/system-prompt.md), loaded as JAMES's system prompt |

Which one you are in is decided by the branch you are on, not by the folder
name. Ask `git rev-parse --abbrev-ref HEAD`.

---

## The boundary is enforced, not just written down

`tools/persistent/check_design_scope.py` runs as **Gate 0** of the pre-commit
hook and is the single authority for which paths belong to the design branch —
this document deliberately does not restate the list, so the two cannot drift:

```bash
python3 tools/persistent/check_design_scope.py --list      # the scope
python3 tools/persistent/check_design_scope.py --against main   # pre-merge
```

Enforcement is **asymmetric**, because the risk is:

- On a **design branch**, staging an engine file is **BLOCKED**. This is the
  guarantee the Director asked for: design work cannot reach the engine.
- On **`main`**, staging a UI file only **WARNS**. CLAUDE.md makes Claude
  engine-only, but the Director commits here too and a hard block would stop
  him working in his own repository.

⚠️ **A branch only gets the gate once it has the file.** The hook lives in the
repository (`core.hooksPath = tools/persistent/hooks`), so a branch created or
left behind before 2026-09-09 is unprotected until it merges `main`.

### The three files both sides genuinely need

These are not accidents; they are the places the split is not yet real. All
three are blocked on a design branch, and the block is a holding action, not a
solution:

| File | Why it is contested |
|---|---|
| `godot/scripts/world/room.gd` | 11 107 lines of engine core that holds **21 hardcoded `$HUD/...` node paths**. Renaming or moving a HUD widget breaks it at RUNTIME with a null `@onready` — a failure no git gate can catch. |
| `project.godot` | The `[input]` section is design's; every other section is the engine's; Godot cannot split the file. |

✅ **The HUD was extracted on 2026-09-09.** `godot/scenes/ui/hud.tscn` holds the
CanvasLayer and its 24 nodes; `room.tscn` instances it in one line and is
engine-owned again. A new panel belongs in `hud.tscn`, which is entirely
design's.

## Engine workspace — `main`

**What belongs here:** voxel rendering (geometry, baking, lighting), physics and
destruction, movement and pathfinding, game systems (prediction, damage, alerts),
architecture and core APIs.

**What does not:** UI/HUD scripts, menu systems, input UI, visual polish.

Scope rules for CLAUDE, per [CLAUDE.md](CLAUDE.md):

- ✅ Engine logic, physics, systems, world state
- ✅ Expose a new engine signal or state container **when the Director asks**
- ✅ Coordinate planes, data structures, calculations
- ❌ Never edit `godot/scripts/ui/`
- ❌ Never modify HUD canvas layouts in `room.tscn`
- ❌ Never write player-facing text — `tr("domain.key")` at the seam

Commit tags: `[FIX]`, `[FEAT]`, `[PERF]`, `[REFACTOR]`, `[DOCS]`, or the
prompt id (`[GLASS-D48]`, `[TARGETING-05]`).

---

## Design workspace — `feat/design-interface-hud`

**What belongs here:** UI scripts under `godot/scripts/ui/`, HUD panels and
windows, input wiring, menu systems, visual polish, interface layout.

**What does not:** core logic, game systems, voxel rendering, coordinate math,
architecture decisions.

Scope rules for JAMES, per [`../JAMES/.qwen/system-prompt.md`](../JAMES/.qwen/system-prompt.md):

- ✅ UI scripts, HUD panels and windows, input actions and signals
- ✅ Implement [INTERFACE_MASTER_PLAN.md](PROMPTS/PLANNING/INTERFACE_MASTER_PLAN.md) tasks
- ❌ Never touch `godot/scripts/systems/`, physics, destruction, prediction
- ❌ Never rewrite game logic or coordinate math
- ❌ Never modify `room.gd` core flow — ask the Director to expose a signal

Follow the `PanelBase` / `WindowBase` pattern
([panel_base.gd](godot/scripts/ui/panel_base.gd),
[window_base.gd](godot/scripts/ui/window_base.gd)); wire reactive signals, never
game logic; `tr("domain.key")` for player-facing text.

Commit tags: `[UI-WAVE1]`…`[UI-WAVE3]`, `[HUD]`, `[INPUT]`, `[DOCS]`.

**Starting a session** (JAMES runs on a PC over LAN):

```bash
cd "/Volumes/Expansion/----- PESSOAL -----/PYTHON/JAMES"
set -a; . ./.env; set +a
./scripts/check-pc-endpoint.sh   # expect: endpoint validated
./scripts/qwen-pc.sh             # or: Serviços → JAMES Qwen Code
```

Credentials live in `JAMES/.env`, which is git-ignored and never committed.

## Verification — identical on both sides

Every commit, either workspace:

```bash
python3 tools/persistent/project_lint.py          # 0 real compile errors
python3 tools/persistent/check_invariants.py      # 0 rule violations
python3 tools/persistent/gen_codemap.py --check   # CODEMAP in sync
python3 tools/persistent/run_selftests.py         # the arbiter for selftests
```

The pre-commit hook runs scope, invariants, CODEMAP freshness and the compile
gate on its own. Never bypass it.

## Syncing and merging

Engine changes flow **main → design** as often as the Director likes:

```bash
cd "/Volumes/Expansion/----- PESSOAL -----/PYTHON/INFILTRAITOR_DESIGN"
git fetch origin main && git merge origin/main
python3 tools/persistent/project_lint.py
git push origin feat/design-interface-hud
```

Interface work flows **design → main** only when the Director merges it, and
only after the pre-merge report is clean:

```bash
python3 tools/persistent/check_design_scope.py --against main
```
