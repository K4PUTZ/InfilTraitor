# INFILTRAITOR — Lighting & Shadow System Design

> **Status:** Foundation planned — M2-13 rewrite  
> **Last updated:** June 2026  
> **Scope:** Permanent environment shadows, directional light sources, parallax depth layers, future interactive light mechanics

---

## 1. Design Intent

Shadows in INFILTRAITOR are **part of the scenery**, not a UI overlay. They are generated by the physical positions of light sources relative to obstacles, rendered as permanent tiles baked into the TileMap at room load time, and covered by Fog of War like any other floor tile. The player reads the lighting environment the same way they read walls and crates — it is always there, it has geometric logic, and it can be anticipated.

**Tactical consequence:** a room with few concentrated light sources creates strong shadow corridors (high stealth value). A well-lit room is uniformly hostile. The player and level designer can reason about this from the tile layout alone.

**Artistic consequence:** coherent directional lighting makes isometric scenes read as physically plausible spaces. Shadows anchor objects to the ground and communicate height differences.

## 2. Three Visual Depth Layers

The scene is composed of three spatial layers rendered at different parallax speeds. Only the middle layer is gameplay-relevant; the others are visual.

```
┌─────────────────────────────────────────────────────────┐
│  UPPER LAYER (ceiling plane)                            │
│  • Light sources (lamps, torches, candles)              │
│  • Ceiling geometry (vents, pipes, second-floor edges)  │
│  • Parallax factor: ~1.08–1.12  (faster, closer)        │
│  • z_index: above all gameplay nodes                    │
│  • Implemented as: CanvasLayer with scroll_offset       │
├─────────────────────────────────────────────────────────┤
│  GAME LAYER (floor plane) ← gameplay lives here         │
│  • Tiles, crates, walls, agent, guards                  │
│  • Shadow tiles baked onto ShadowLayer TileMapLayer     │
│  • Parallax factor: 1.0 (reference)                     │
│  • z_index: standard TileMap hierarchy                  │
├─────────────────────────────────────────────────────────┤
│  LOWER LAYER (sub-floor plane)                          │
│  • Water, lava, smoke, grates, vents below floor        │
│  • Visible through holes/openings defined in TileMap    │
│  • Parallax factor: ~0.88–0.92  (slower, farther)       │
│  • Implemented as: CanvasLayer with scroll_offset       │
└─────────────────────────────────────────────────────────┘
```

**Parallax implementation (future):**
```gdscript
# In _process(), for both parallax CanvasLayers:
var cam_pos := camera.global_position
upper_layer.offset = cam_pos * (UPPER_PARALLAX - 1.0)   # e.g. 0.10
lower_layer.offset = cam_pos * (LOWER_PARALLAX - 1.0)   # e.g. -0.10
```

The upper and lower layers have no gameplay collision or interaction — they are purely cosmetic. The parallax effect creates perceived depth without requiring actual multi-floor tile logic.

## 3. Light Source Data Model

```gdscript
class_name LightSource
extends RefCounted

enum LightType {
    CEILING_LAMP,    ## Fixed overhead — strongest, widest radius
    WALL_TORCH,      ## Directional cone from wall mount
    CANDLE,          ## Very short radius, can be extinguished
    SUNLIGHT,        ## Directional, infinite radius — outdoor maps
    EMERGENCY,       ## Red, activates on alarm, rotates
    BROKEN,          ## Flickers — intermittent shadow effect
}

var cell: Vector2i         ## Tile position of the light source
var type: LightType
var height: float          ## Height above floor plane (in tile units)
                           ## CEILING_LAMP: ~5.0, WALL_TORCH: ~2.5, CANDLE: ~0.5
var radius: int            ## Effective radius in tiles
var intensity: float       ## 0.0–1.0, affects shadow depth
var active: bool = true
var direction: Vector2     ## For directional lights (SUNLIGHT, WALL_TORCH)
                           ## Vector2.ZERO = omnidirectional
## Future interactive properties (declared, not implemented yet):
var hackable: bool = false
var breakable: bool = false
var flicker: bool = false   ## Visual only — does not change shadow tiles each frame
var alarm_activated: bool = false  ## For EMERGENCY type
```

## 4. Shadow Calculation Algorithm

### 4.1 Per light source, per obstacle

```
For each LightSource L (active):
  For each blocked_cell O within L.radius:
    
    1. Compute direction vector: raw_dir = (O.cell - L.cell)
    2. Quantize to 8 directions (N/NE/E/SE/S/SW/W/NW)
    3. Compute shadow length using height geometry:
         shadow_length = O.height × (L.height - O.height) / distance(L, O)
         clamped to [0, SHADOW_MAX_LENGTH]
    4. For step i in [1 .. ceil(shadow_length)]:
         shadow_cell = O.cell + dir * i
         falloff = 1.0 - (i / shadow_length)   ## linear falloff
         mult = lerp(SHADOW_MULT_DIRECT, 1.0, 1.0 - falloff)
         _shadow_tiles[shadow_cell] = min(existing, mult)
```

### 4.2 Ambient occlusion fallback (no light sources)

If `_light_sources` is empty, fall back to the previous omnidirectional algorithm:
each blocked cell projects `SHADOW_MULT_DIRECT` on all 4 adjacent tiles,
and `SHADOW_MULT_PENUMBRA` on tiles 2 steps away.

This ensures outdoor/open maps with no explicit lights still have minimal shadow data
for detection multipliers, even without visual shadow tiles.

### 4.3 Fully lit tile (no shadow)

A tile that has direct LOS to at least one active light source and is NOT in the shadow
cone of any obstacle receives `mult = 1.0` — full detection probability, no shadow tile placed.

## 6. Light Source Types — Design Reference

| Type | Height | Radius | Intensity | Shadow character | Interactive |
|------|--------|--------|-----------|------------------|-------------|
| **Ceiling lamp** | 5.0 | 6–8 | 0.9 | Long, sharp, radial from lamp position | Hackable, breakable |
| **Wall torch** | 2.5 | 4–5 | 0.7 | Medium, directional (away from wall) | Can be extinguished |
| **Candle** | 0.5 | 2–3 | 0.5 | Short, soft, all directions | Extinguishable by agent |
| **Sunlight** | ∞ | ∞ | 1.0 | Parallel, long, fixed direction per zone | No (environmental) |
| **Emergency** | 3.5 | 3 | 0.6 | Short, red, sweeps — baked at alarm angle | Alarm-triggered |
| **Broken/flickering** | 4.0 | 5 | 0.4–0.8 | Intermittent — baked at OFF state | Can be triggered |

**Sunlight direction by zone:**

| Zone | Sun direction | Rationale |
|------|--------------|-----------|
| Corporate HQ (indoor) | None (artificial only) | — |
| Jungle Outpost | SW | Afternoon tropical sun |
| Arctic Base | S (low angle) | Polar sun near horizon |
| Space Station | None (starfield) | Zero natural shadow |
| Open field map | SE or SW | Configurable per mission |

## 7. Shadow Tile Rendering — TileMapLayer Architecture

```
FloorLayer          z_index = 0   (base floor tiles)
ShadowFullLayer     z_index = 1   (direct shadow tiles — darkest)
ShadowPartialLayer  z_index = 1   (penumbra tiles — lighter)
StructureLayer      z_index = 10  (crates, terminals)
StructureWallLayer  z_index = 10  (walls)
FogOfWarOverlay     z_index = 12  (covers all of the above)
MovementOverlay     z_index = 5   (shows through FOW in visible area)
Agent / Guards      z_index = 10  (above floor, below FOW)
```

Shadow tiles use the same `floor_SE` (or theme floor) tile with `modulate` set per layer:

```gdscript
shadow_full_layer.modulate    = Color(0.58, 0.58, 0.58, 1.0)  ## 42% darker
shadow_partial_layer.modulate = Color(0.78, 0.78, 0.78, 1.0)  ## 22% darker
```

The FOW covers both shadow layers normally — as the player explores, shadows are
revealed like any other floor tile. This is intentional: the player discovers the
shadow layout as they navigate, creating planning decisions on approach.

## 8. Interactive Light Mechanics (Future — M4+)

These are declared as design intent. Implementation deferred until after M3 (procedural generation).

### 8.1 Extinguishing (candle, torch)
- Cost: 1 AP, adjacent tile
- Effect: removes light source from `_light_sources`, recomputes `_shadow_tiles`, rebakes `ShadowLayer`
- Guard reaction: if guard has LOS to the now-dark tile, enters SUSPICIOUS for 3 turns
- Sound: soft noise (candle) or moderate noise (torch — sizzle)

### 8.2 Hacking (ceiling lamp, camera-linked lights)
- Cost: 1–2 AP, terminal or adjacent panel
- Effects:
  - **Disable**: same as extinguish but silent
  - **Flicker**: lamp turns on/off every 2 turns — shadow tiles baked for OFF state; ON state reverts to full light
  - **Redirect**: change lamp's effective direction — useful for creating shadow where there was none

### 8.3 Breaking (lamp, fixture)
- Cost: 1 AP (throw object) or melee strike
- Effect: permanent disable, louder noise (broken glass), debris tile placed
- Guard reaction: investigates loudly, STATE_ALERT

### 8.4 Alarm-activated lights (emergency lamps)
- Triggered by `_on_guard_alarmed()` signal in room.gd
- Rebakes shadow tiles with emergency lamp added to `_light_sources`
- Emergency lamps typically illuminate previously dark stealth corridors — tactical pressure during alarm

### 8.5 Agent-carried light (future gadget)
- Flashlight / night-vision: reveals tiles beyond normal FOW but creates noise and visible light cone
- Enemies with LOS to the light can see it from farther than normal vision

## 9. Shadow and Detection Multipliers — Combined Stack

All multipliers apply multiplicatively in `evaluate_detection()`:

```
final_prob = base_prob
           × lateral_mult          (FOV angle falloff)
           × state_prob_mult        (PATROL/ALERT/CHASE etc.)
           × shadow_mult            (from _shadow_tiles, 0.30–1.0)
           × cover_mult             (COVER_FULL=0.15, PARTIAL=0.50)
           × posture_mult           (STANDING=1.0, CROUCHING=0.55, PRONE=0.20)
```

Theoretical minimum (prone + full cover + deep shadow):
`1.0 × 1.0 × 0.55 × 0.30 × 0.15 × 0.20 ≈ 0.005` — near invisible.

This is intentional: a skilled player who stacks all stealth modifiers in PATROL state
becomes almost undetectable. In CHASE state (`prob_mult = 2.80`), the same stack gives:
`1.0 × 1.0 × 2.80 × 0.30 × 0.15 × 0.20 ≈ 0.025` — still very low but not zero.
The guard is alerted and searching hard but the agent in deep cover is still viable.
